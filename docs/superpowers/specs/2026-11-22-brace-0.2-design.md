# BRACE 0.2 — design

Date: 2026-11-22 · Status: draft for approval · Owner: Marco Dolce

## Intent

V.A.N.T.A. 0.1.0 works well for its author, but using it means remembering slash commands (`/vanta:stress-test`, `/vanta:decision`, …). The author doesn't type them, so the tools go unused. At the same time the plugin is about to reach other people (LinkedIn now, an Instagram page soon), and its name collides with Vanta, a well-known software company.

Version 0.2 turns the plugin into **BRACE**: one plugin for everyone, from a beginner in the claude.ai chat to an advanced user in the terminal, that people use by **talking normally**. Claude works out which tool to start.

## Goals

1. **Rename** to BRACE everywhere (written exactly `BRACE`: uppercase, no dots).
2. **English is the source** of the repository and of the plugin. Italian stays as a translation derived from English, with an automatic alignment check.
3. **Natural-language activation**: no slash command is ever needed. Slash commands stay available for those who want them.
4. **One plugin, three levels**: base in chat (web and desktop app), full in Cowork and Claude Code. Same skills, which adapt to the environment they find.
5. **Memory in chat** through the knowledge of a Claude Project.

## Non-goals

- Shortening or "drying out" the skills. Their content and procedures stay as in 0.1.0, apart from what this document changes.
- New analytical features (multi-turn wargame, dashboards, and so on).
- The full eval campaign. That is step 4 of the roadmap, after 0.2 ships. 0.2 only renames and translates the existing evals and adds routing cases (see Evals).
- Renaming the GitHub repository. That is the owner's action, outside the code. GitHub redirects the old URL.

## Anti-goals (failure even if it technically works)

- A user in chat has to know a command name to get a tool.
- Something expensive (the agent-based wargame, the independent critic) starts without the user agreeing to the cost.
- The plugin silently does less in chat than in Claude Code. Every fallback must be stated.
- `PUNTO NAVE` stops working, or behaves differently from today.
- The Italian and English versions drift apart.

## Constraints

- **Platform support** (claude.com/docs/plugins/platform-support, checked 2026-11-22): plugin **skills** work in claude.ai chat, the desktop app, Cowork and Claude Code. **Hooks and sub-agents** run only in Cowork and Claude Code; in chat they are grayed out. Output styles exist only in Claude Code.
- In chat, files written by a skill do not survive between conversations.
- The existing decision-log format is parsed by the startup hook (`awk` on `## ID`, `- Revisione:` / `- Review:`, `- Stato:` / `- Status:`). Any format change must keep the hook working.
- There is a single (semi-private) user base today, so breaking `/vanta:*` command names is acceptable.

## Approaches considered

| | Approach | Trade-off | Outcome |
|---|---|---|---|
| A | Rewrite each skill's `description` with the phrases people actually use; unlock the wargame with a cost confirmation | Simple and native. Vague requests ("I don't know whether to take this job") trigger no skill and get a plain answer without the method. | Included in B |
| **B** | **A, plus `method` becomes the entry point**: its description catches any decision, doubt, plan or evaluation request, even a vague one. It applies the method and hands off to the right tool when warranted. | One skill gets a broader role; no new skill. Every request enters the system. | **Chosen by the owner** |
| C | Merge everything into one large skill with reference files | Easiest for routing, but removes the separate commands advanced users want and means a full rewrite. Goes against "from basic to advanced". | Rejected |

## Design

### 1. Naming

| Item | 0.1.0 | 0.2 |
|---|---|---|
| Marketplace name | `vanta` | `brace` |
| English plugin (source) | `plugins/vanta-en`, name `vanta-en` | `plugins/brace`, name `brace` |
| Italian plugin (derived) | `plugins/vanta`, name `vanta` | `plugins/brace-it`, name `brace-it` |
| `displayName` | V.A.N.T.A. | BRACE |
| State folder | `.vanta/` | `.brace/` |
| Output style | `V.A.N.T.A.` | `BRACE` |
| Install | `/plugin install vanta@vanta` | `/plugin install brace@brace` (Italian: `brace-it@brace`) |

The acronym expansion (*Bias · Risks · Assumptions · Confidence · Evidence*) appears **at most once**, as the README subtitle. Everywhere else it is just `BRACE`. *(Builder's call, agreed in conversation; the owner may remove it.)*

Skill, agent and state-file names keep their 0.1.0 names in each language: `method`, `position-fix`, `stress-test`, `wargame`, `decision`, `review`; `nemesis`, `red`, `blue` / `metodo`, `punto-nave`, … `nemesi`, `rosso`, `blu`.

**Migration from `.vanta/`:** the hook reads `.brace/` and falls back to `.vanta/` when `.brace/` is missing. The first skill that writes state, finding `.vanta/` and no `.brace/`, renames the folder to `.brace/` and says so in one line.

### 2. English source, Italian derived

- `plugins/brace` is the only place where content is designed and changed first.
- `plugins/brace-it` is a translation: same files, same structure, same frontmatter keys, same headings, same version number. Content is translated, not re-designed.
- **Parity check** (`scripts/check-parity`, run in CI on every push and PR):
  - same relative file set (accounting for the documented skill, agent and file-name mapping table, kept in the script);
  - same frontmatter keys per file, with identical values for non-text keys (`model`, `tools`, `disable-model-invocation`, `argument-hint` placeholders aside);
  - same number of `#`/`##` headings per file;
  - same `version` in both `plugin.json` files and in `CHANGELOG.md`;
  - `claude plugin validate` passes for both plugins, if available in CI; otherwise the check validates JSON syntax only.
- CI also runs `shellcheck` on the hook scripts.
- README: `README.md` becomes English (the current `README.en.md`), and the Italian one becomes `README.it.md`.

### 3. Natural-language activation (approach B)

**3a. Descriptions.** Every skill's `description` is rewritten around what users say, not around keywords. Each description lists realistic trigger phrasings in **both English and Italian**, whichever plugin it belongs to, because users type in their own language. Existing keywords stay as extra triggers. Examples of target phrasings:

- `stress-test`: "how could this go wrong", "poke holes in this", "what am I missing", "come potrebbe andare storto", "trova i punti deboli".
- `decision`: "I've decided to…", "note this down", "let's go with X", "ho deciso di…", "segnati questa scelta".
- `review`: "how did my past decisions go", "was I right", "com'è andata con le decisioni", "avevo ragione?".
- `position-fix`: "where are we", "sum up where we stand", "facciamo il punto".
- `wargame`: "how would competitors react", "simulate the other side", "come reagirebbe il mercato".

**3b. `method` as the entry point.** Its description covers any request to decide, choose, evaluate, judge a plan or check reasoning, including vague and emotional ones ("I'm not sure whether to…", "is this a good idea?"). Its body gains a short **routing section**. After answering with the method, it proposes the next tool when one adds value, in one line and without starting it:

- hard-to-reverse choice → offer `stress-test`;
- choice that depends on how others react, with high stakes → offer `wargame`;
- the user has just decided → offer to record it with `decision`;
- long or drifting conversation → offer `position-fix`.

Cheap tools (`position-fix`, `decision`, standard `stress-test`) may start directly when the user's request clearly asks for them. Expensive modes always ask first (see 3c).

**3c. Wargame unlocked.** `disable-model-invocation: true` is removed. The skill's first step becomes a **cost gate**: when agents are available, state in one line that the agent mode costs several normal answers and wait for a yes, or offer the quick mode. The independent `stress-test` mode keeps its existing one-line cost warning and also waits for a yes when it was not explicitly requested.

**3d. `PUNTO NAVE` unchanged.** `PUNTO NAVE` (and `STOP`) keep triggering the position fix exactly as today, with the same format and the same saving behaviour. Both plugins recognise `PUNTO NAVE`; the English one also recognises `POSITION FIX`.

**3e. Output style.** Renamed `BRACE`. Its closing line points to the natural-language way of using the tools, not to slash commands.

### 4. Three levels, one plugin

Each skill detects its capabilities at run time and uses the richest path available. It never relies on knowing the product name of the environment.

| Capability check | If available | If not |
|---|---|---|
| Can delegate to a sub-agent (`nemesis`, `red`, `blue`) | independent critic / agent wargame (after the cost gate) | run the same procedure in this conversation, and say in one line that the critique is less independent here and that Cowork or Claude Code would run it with a separate agent |
| Can read and write a persistent project folder (Claude Code, Cowork) | state in `.brace/`, as today | Project memory (section 5) |
| Startup hook ran (state injected at session start) | resume from the injected position fix | look for BRACE files in the Project knowledge (section 5) |

Resulting levels:

| | Chat (web, app) | Cowork | Claude Code |
|---|---|---|---|
| Method, stress test, decision, review | yes | yes | yes |
| Independent critic | in-conversation, stated | agent | agent |
| Wargame | quick, stated | agents | agents |
| Memory | Project knowledge | `.brace/` | `.brace/` |
| Automatic resume and due-review reminder | no | yes | yes |
| Output style, slash commands | slash only | slash only | both |

### 5. Memory in chat: Claude Projects

When there is no persistent folder:

- **Writing.** `position-fix`, `decision` and `review` show the result and then the **full updated file** in a single code block. They then give a one-line instruction: add it to (or replace it in) the Project knowledge as `brace-position-fix.md` / `brace-decisions.md` (Italian: `brace-punto-nave.md` / `brace-decisioni.md`). The log is always given in full, never as a fragment, so the user replaces one file instead of merging. The same file format as `.brace/` is used, so a user can later move the files into a folder and Claude Code picks them up.
- **Reading.** At the start of relevant work, and inside `review`, the skill checks the Project knowledge (and any uploaded file) for these files and uses them, confirming with the user that the position fix is still valid (as today).
- **Not in a Project.** The skill says once that memory lasts only for this chat. It suggests creating a Project and still shows the content so the user can keep it.
- **Calibration** in `review` is computed by counting from the file. If a code tool is available, it runs the count with code.
- Claude's own memory feature is not relied on (rejected: format not controllable, so calibration becomes unreliable).

### 6. Evals in 0.2

- Rename and translate the existing six cases per language to the new names.
- Add **routing cases** (both languages): natural-language prompts with no command and no keyword, each graded on whether the right skill started or was offered. At least one each for stress-test, decision, review, position-fix and wargame (offer with cost gate, not run). Include one vague request that must enter `method`. Include one `PUNTO NAVE` case unchanged from today.
- Running the full eval campaign and publishing results is out of scope (roadmap step 4).

### 7. Documentation and release

- README (EN source, IT translation): new name, a three-step install for chat users (Customize → Plugins in claude.ai or the desktop app), the terminal install, "just talk to it" usage with examples, the levels table, how to use a Project for memory in chat, and migration notes from V.A.N.T.A.
- `CHANGELOG.md`: version **0.2.0**, listing the breaking renames.
- Remove the README section about the name clash.

## Decided by the owner

- Name BRACE, without dots, "for now".
- English is the source; Italian is derived and checked automatically.
- Approach B; the work order above.
- One plugin for everyone: base in chat, full in Cowork and Claude Code.
- Chat memory through Claude Projects.
- `PUNTO NAVE` must not change.
- The skills are not shortened.

## Builder's calls (in this document, changeable)

- Plugin ids `brace` / `brace-it`, folder `.brace/`, migration from `.vanta/`.
- Acronym expansion only as the README subtitle.
- Bilingual trigger phrases in every description.
- Both plugins recognise `PUNTO NAVE`.
- Chat file names `brace-position-fix.md`, `brace-decisions.md` and Italian equivalents.
- Parity rules and CI contents in section 2.

## Settled after the builder check

- **Italian text.** Keep the existing Italian content as the base: it is the owner's language and already matches English structurally. From 0.2 on, changes are designed in English and then translated into Italian. Only the 0.2 changes are translated now; there is no full re-translation.
- **Description length.** Respect the skill-description limit (1,024 characters). If a description doesn't fit, cut in this order: first the other language's trigger phrases (keep two or three), then the descriptive text. Keywords (`PUNTO NAVE`, `STRESS TEST`, …) are short and always stay.
- **One plugin at a time.** Users install `brace` *or* `brace-it`, as in 0.1. The README says so. No double-run guard is needed in the hook.
- **File names.** Hook and skills accept both the plain names (`decisions.md`) and the chat names (`brace-decisions.md`, and the Italian equivalents) inside `.brace/`. Moving files from a Project into a folder then works without renaming.

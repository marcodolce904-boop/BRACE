# BRACE 0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the V.A.N.T.A. 0.1.0 plugins into BRACE 0.2.0. English is the source, Italian is derived and parity-checked, skills start from natural language, and the same skills adapt from claude.ai chat up to Claude Code.

**Architecture:** The plugins are Markdown skills, agents and an output style, plus one POSIX `sh` SessionStart hook. Correctness is enforced by two stdlib-only Python checkers, plus a shell test for the hook, all run in GitHub Actions:
- `scripts/check_plugin.py` checks the content rules of one plugin;
- `scripts/check_parity.py` checks EN↔IT alignment.

Content tasks are TDD'd against those checkers: add the rule and its fixture test, watch the real plugin fail, then edit the Markdown until it passes.

**Tech Stack:** Markdown + YAML frontmatter, POSIX sh + awk, Python 3 (stdlib `unittest` only), GitHub Actions, `claude plugin validate` (available locally; optional in CI).

**Spec:** `docs/superpowers/specs/2026-11-22-brace-0.2-design.md`

## Global Constraints

- The name is written exactly `BRACE`: uppercase, no dots. The acronym expansion *Bias · Risks · Assumptions · Confidence · Evidence* appears only once, as the README subtitle.
- Marketplace `brace`. English plugin `plugins/brace`, name `brace`. Italian plugin `plugins/brace-it`, name `brace-it`. `displayName` `BRACE`. Version `0.2.0`.
- State folder `.brace/`, with read fallback to `.vanta/`. The first state write renames `.vanta/` to `.brace/` and says so in one line.
- State file names: EN `position-fix.md`, `position-fix-history.md`, `decisions.md`. IT `punto-nave.md`, `punto-nave-storico.md`, `decisioni.md`. Chat/Project names `brace-<same name>` (e.g. `brace-decisions.md`) are accepted everywhere.
- Skill, agent and file names keep their 0.1.0 names per language.
- `PUNTO NAVE` (and `STOP`) behave exactly as in 0.1.0, in both plugins. EN also accepts `POSITION FIX`.
- Skill content is not shortened. Only the sections this plan names are added or changed.
- Skill `description` ≤ 1,024 characters. When cutting: first the other language's phrases (keep at least 2), then descriptive text. Never cut keywords.
- Expensive modes (agent wargame, unrequested independent critic) always wait for a yes.
- Every fallback is stated to the user in one line.
- Install one plugin at a time; the README says so.
- The existing Italian text is the base: translate only what this plan changes.
- No secrets, no network calls in scripts. Python stdlib only.

## Review Focus

1. A decision log written by hand, with extra spaces or Windows line endings (`- Review:  2026-11-03\r`): the hook must still report it as due. → test in Task 3.
2. A project that has both `.vanta/` and `.brace/`: `.brace/` wins, and the hook never prints the state twice. → test in Task 3.
3. A folder with neither `.brace/` nor `.vanta/`: the hook prints nothing, as today. → test in Task 3.
4. A description that grows past 1,024 characters after adding the bilingual phrases: the checker must fail loudly instead of the platform silently truncating it. → test in Task 1.
5. An EN-only edit with no IT counterpart (a new file, or a new `##` heading): parity must fail. → test in Task 2.

- [ ] **Step 1: Write `tests/test_hooks.sh`.** It is POSIX sh: it builds temp project dirs, runs each hook with `CLAUDE_PROJECT_DIR` and `BRACE_TODAY=2026-12-01`, and asserts with `grep -q` / `[ -z ]`.
